# תפעול

## תהליכים
| תהליך | פקודה | הערות |
|---|---|---|
| ווב | `npm start` (אחרי `npm run build`) | stateless; אפשר כמה מופעים |
| worker | `npm run worker` | אפשר כמה מופעים – pg-boss ו-`FOR UPDATE SKIP LOCKED` מונעים עיבוד כפול |
| migrations | `npm run db:migrate` | בתפקיד הבעלים; מתקין סכמת pg-boss ויוצר תורים |

בדיקות: `GET /api/health` (חיות), `GET /api/ready` (תצורה, מסד, תור).

## עבודות רקע (pg-boss, אזור זמן Asia/Jerusalem)
| תור | תזמון | תפקיד |
|---|---|---|
| provider-event | בכל אירוע | עיבוד callback סליקה / הודעת וואטסאפ נכנסת |
| sweep | כל דקה | אירועים שנשארו `received` (enqueue שאבד / קריסה), outbox, שליחת הודעות שהגיע זמנן, סימון `sending` תקוע כ-`unknown` |
| poll-open-payments | כל 5 דקות | בירור מול הספק לבקשות פתוחות (סגירת דפדפן / callback אבוד) |
| reminder-scan | א׳–ה׳ 07:00 | תזמון תזכורות לחלון 10:00 |
| reconcile | 03:30 | התאמה יומית מול הספק; הבדלים → משימת reconciliation |
| subscriptions | 04:00 | מחזור מנוי: חשבונית, חיוב, חסד, השעיה |

כל handler אידמפוטנטי ורץ בהקשר tenant מפורש.

## התאמות וחריגים
- חריגי סליקה (אימות נכשל, סכום/חשבון/בקשה לא תואמים, החזר שלא ניתן להחיל) → Task `provider_exception` אצל הגבאי. אין הפחתת חוב.
- `UnroutedEvent` – callbacks מחשבון לא מוכר / גוף לא קריא (נשמר hash בלבד).
- אם לספק אין API רשימה – נפתחת SupportCase "נדרש ייבוא דוח ידני". לא מוצג כאוטומציה.
- קבלה שנכשלה: עד 5 ניסיונות עם backoff, אחר כך Task `receipt_failed`. החיוב נשאר.

## ניטור (מינימום לפני השקה)
- `ProviderEvent` בסטטוס `received` מעל 10 דקות; `exception` חדשים.
- `PaymentAttempt` פתוחים מעל שעה.
- `OutboundMessage` בסטטוס `unknown`/`failed`.
- `pgboss.job` בסטטוס failed; worker שלא עובד (אין ריצת sweep בדקות האחרונות).
- התראות כוללות מזהים וספירות בלבד – לא שמות, טלפונים או סכומים של מתפללים.

לוגים: JSON, ללא פרטים אישיים, ללא טוקנים (טוקן הקישור ב-fragment ולכן לא מגיע לשרת).

## גיבוי ושחזור
```bash
scripts/backup.sh                       # pg_dump מלא (סכמה, נתונים, הרשאות, RLS) → backups/*.dump
scripts/restore-check.sh backups/X.dump # משחזר למסד זמני ומשווה טביעת אצבע של ספר החשבונות
```
טביעת האצבע כוללת ספירת תשלומים/הקצאות/נדרים/החזרים וחוב+זכות מחושבים לכל כרטיס. בוצע בהצלחה ב-30.09.2026 (ראו FINAL_REPORT).
בייצור: גיבוי יומי + WAL/PITR של ספק המסד, שמירה מוצפנת מחוץ לאתר, תרגול שחזור רבעוני.

## תקלות נפוצות
| תסמין | בדיקה | פעולה |
|---|---|---|
| תשלום בוצע אך החוב לא ירד | `ProviderEvent` של הבקשה; Task פתוח | אם `received` – worker לא רץ; אם `exception` – לפי הסיבה במשימה |
| תזכורות לא נשלחות | מסך תזכורות → סיבת דילוג | הסכמה/חיבור/מכסה/מנוי |
| מתפלל לא מקבל קוד | הגבלת תדירות (3 ל-15 דק׳) | להמתין / קישור חדש |
| החלפת חשבון סליקה | החשבון הישן `replaced` | עסקאות ממתינות ממשיכות להיפתר מולו |

## הרשאות מסד
- `synagogue_app` – ריצה בלבד, RLS חל עליו תמיד. אין UPDATE על סכומים ואין DELETE על תנועות.
- `synagogue_owner` – migrations, גיבוי. לא לשימוש האפליקציה.
