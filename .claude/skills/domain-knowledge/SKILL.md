# Domain Knowledge

The domain can be anything (gym, school, fleet, restaurant, real-estate, events, a hobby app...). The method below is the main tool; the packs are just shortcuts.

## Method – do this for every domain (in my head, write only the result)
1. **Who**: actors and what each needs to get done (jobs-to-be-done).
2. **What**: core entities + relations; the main entity's lifecycle states.
3. **Flows**: the 3–7 things users do daily/weekly; happy + failure path.
4. **Money & time**: payments, pricing, invoices, deadlines, reminders, recurring events.
5. **Rules**: Israeli regulation that applies (privacy, consumer, tax, accessibility, sector-specific) – quick `research` if unsure.
6. **Measure**: the 3–5 KPIs the owner checks; the reports they'd print.
7. **Pitfalls**: what goes wrong in real life (double booking, duplicates, offline, permissions leaks).
8. **Best-in-class**: what leading products in this space do that users love – borrow the ideas, not the look.
Scale the depth to the request: a small app needs steps 1–3 in two minutes; a large system needs all.
